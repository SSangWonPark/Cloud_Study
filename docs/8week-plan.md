## 1단계. 이론 공부 (1~2주차)

### 1주차 — 클라우드 개념 + 리눅스/네트워킹 기초
**목표**: AWS 콘솔을 열기 전에, "클라우드가 뭘 대체하는 건지"를 몸에 익히기.

- 월~화: 리눅스 기본 (Linux Journey 완주 목표) — 파일시스템, 권한(chmod/sudo), 프로세스, SSH 키 접속
- 수~목: 네트워킹 기초 — IP/서브넷/CIDR 계산, DNS 동작 원리, TCP/UDP, HTTP vs HTTPS/TLS 개념
- 금: Git/GitHub 워크플로 정리 (이미 쓰고 있지만, 브랜치 전략과 `.gitignore` 원칙 한 번 복습 — 이후 인프라 코드를 여기 저장소에 커밋할 것이므로)
- 주말: **AWS Cloud Practitioner Essentials**(Skill Builder, 무료) 강의 시작 — 리전/AZ, IaaS/PaaS/SaaS, 공동 책임 모델 파트까지

**산출물**: 리눅스/네트워킹 핵심 개념을 본인 언어로 정리한 짧은 메모 (`docs/notes/week1.md` 같은 형식 추천)
**체크리스트**: [ ] SSH 키 페어 직접 만들어서 로컬 VM이나 WSL에 접속해봤다 [ ] 서브넷 마스크 계산을 손으로 한 번 해봤다

### 2주차 — AWS 코어 서비스 이론 + 계정 셋업
**목표**: AWS 계정을 안전하게 세팅하고, Phase 1 서비스들의 "이름과 역할"을 이론으로 먼저 익히기.

- 월: AWS 계정 생성 직후 **3대 안전장치** 적용 — 루트 계정 MFA, IAM 관리자 사용자 생성 후 루트 잠그기, Billing 콘솔에 Budget Alert($5~10) 설정. 이번 계획에서 가장 먼저, 가장 중요하게 처리
- 화~수: Cloud Practitioner Essentials 마저 완주
- 목~금: 「AWS를 다루는 기술」(또는 대체 자료) 앞부분으로 IAM/VPC/EC2/S3 개념 정리 — 아직 실습은 안 해도 됨, "이게 왜 필요한지"만 이해
- 주말: RDS, ELB/Auto Scaling, Route53/CloudFront 개념 훑기 + Billing/Cost Explorer 화면 미리 구경

**산출물**: IAM/VPC/EC2/S3 각각을 한두 문장으로 설명할 수 있는 정리 노트
**체크리스트**: [ ] MFA 설정 완료 [ ] Budget Alert 설정 완료 [ ] IAM 관리자 계정으로 로그인 확인 [ ] 루트 계정 로그인 안 하고도 작업 가능한 상태

## 2단계. 실습 (3~5주차)

### 3주차 — 입문 실습: 정적 사이트 + 첫 EC2
**목표**: "콘솔 클릭 → 리소스 생성 → 접속 확인 → 비용 확인"의 전체 사이클을 손에 익히기.

- 월~화: [Launch a Virtual Machine](https://aws.amazon.com/getting-started/hands-on/launch-a-virtual-machine/) 튜토리얼 그대로 따라 EC2(또는 Lightsail) 인스턴스 띄우고 SSH 접속
- 수~목: S3 버킷 생성 → 정적 웹사이트 호스팅 설정 → CloudFront 연결까지 (AWS Hands-On 허브의 "Host a Static Website" 활용)
- 금: 만든 리소스를 하나씩 지워보면서 "삭제 순서"와 "숨은 과금 포인트"(EBS 볼륨, 탄력적 IP 미사용 등) 확인
- 주말: VPC를 콘솔에서 직접 만들어보기 — 퍼블릭/프라이빗 서브넷 나누고, 보안그룹 규칙을 최소 권한으로 설정

**산출물**: 정적 사이트 배포 실습 스크린샷/기록을 `docs/study-log.md`에 남기기
**체크리스트**: [ ] EC2 인스턴스 SSH 접속 성공 [ ] S3+CloudFront로 사이트 접속 성공 [ ] 실습 후 리소스 정리(과금 확인)까지 완료

### 4주차 — 중급 실습: EC2 서버를 직접 구축하고 운영해보기 *(재수정: 목표가 "서버를 직접 운영하는 경험"이므로 EC2+Nginx로 확정)*
**목표**: 이미 만들어둔 실제 프로젝트(Flask 주식 대시보드)를 EC2 서버에 올려서 상시 서비스로 운영해보기. 서버리스는 "서버를 관리하지 않는" 경험이라 이번 목표(서버를 직접 구축·운영)와는 맞지 않아 제외.

- 월: EC2 인스턴스 생성, Python/Flask 실행 환경 구성
- 화~수: 대시보드 코드 배포, systemd로 서비스 등록(재부팅/장애 시 자동 재시작)
- 목: Nginx 리버스 프록시 구성, 도메인 연결(있다면) 또는 Route53으로 서브도메인 발급
- 금: HTTPS 적용 (ACM 또는 Certbot)
- 주말: 부하를 걸어보거나 일부러 프로세스를 죽여보면서 재시작이 잘 되는지 확인 → 느낀 점을 `docs/study-log.md`에 정리

**산출물**: `apps/stock-dashboard/` 폴더에 배포 스크립트·설정 커밋, 실제 접속 가능한 URL
**체크리스트**: [ ] HTTPS로 접속 가능 [ ] 서버 재부팅 후에도 서비스 자동 기동 확인 [ ] 프로세스를 죽였다가 복구되는지 확인 [ ] Nginx 로그 위치 파악

### 5주차 — 심화 실습: Terraform으로 코드화 + CI/CD
**목표**: 지금까지 콘솔로 만든 것을 "코드"로 재현할 수 있게 만들기.

- 월~화: [Terraform: AWS Get Started](https://developer.hashicorp.com/terraform/tutorials/aws-get-started) 튜토리얼 (install-cli → aws-create → aws-manage) 진행
- 수~목: 4주차의 EC2+VPC+보안그룹 구성을 Terraform 코드로 다시 작성 (`infra/terraform/stock-dashboard/`) — 기존 리소스는 지우고 코드로 재생성해보는 것을 추천 (재현성 체감에 제일 좋음)
- 금: GitHub Actions로 "코드 푸시 → 배포 스크립트 실행" 파이프라인 최소 버전 구성
- 주말: [Introduction to Terraform on AWS](https://catalog.workshops.aws/terraform101) 워크숍으로 심화

**산출물**: `infra/terraform/`에 커밋된 코드, 이 코드만으로 인프라를 처음부터 다시 만들 수 있는 상태
**체크리스트**: [ ] `terraform destroy` 후 `terraform apply`로 동일 환경 재생성 성공 [ ] `.gitignore`로 `*.tfstate`, `*.tfvars` 제외 확인 [ ] CI 파이프라인 1회 이상 성공

## 3단계. 클라우드 구축 (6~7주차)

여기서부터가 "진짜 구축"입니다. 지금까지는 학습용 실습이었다면, 6~7주차는 본인 연구 프로젝트를 실제로 클라우드 아키텍처로 재설계·배치하는 단계입니다.

### 6주차 — PDF-Ontology-RAG 아키텍처 설계 및 구축 착수
- 월: 아키텍처 설계 — Neo4j(EC2 self-host vs Aura Free 결정), RAG API 위치(EC2/ECS/Lambda 결정), PDF 저장(S3), 프론트(S3+CloudFront). `docs/roadmap.md`의 참고 아키텍처 다이어그램을 본인 프로젝트에 맞게 수정
- 화~수: Neo4j 인스턴스 구축 (예전에 해둔 Neo4j Docker→클라우드 마이그레이션 분석을 실제로 적용)
- 목~금: RAG API 컨테이너화(Docker) 및 배포
- 주말: S3에 PDF 원본 업로드 파이프라인 연결, 프론트엔드 배포

**산출물**: 전체 서비스가 실제로 동작하는 상태 (아직 다듬어지진 않아도 됨)
**체크리스트**: [ ] 외부에서 API 호출 시 실제 RAG 응답 수신 [ ] Neo4j 데이터 영속성 확인(재부팅 후 데이터 유지)

### 7주차 — 구축 마무리·통합·문서화
- 월~화: 6주차에서 콘솔로 만든 부분을 Terraform 코드로 옮기기 (`infra/terraform/pdf-rag/`)
- 수: 서비스 간 연결 안정화 — 타임아웃, 에러 핸들링, 재시도 로직 점검
- 목: 아키텍처 다이어그램 최종화, `docs/architecture/pdf-rag.md`로 문서화
- 금~주말: 전체 시연 테스트 (처음부터 끝까지 PDF 업로드 → 지식그래프 반영 → 질의응답까지)

**산출물**: 코드화된 인프라 + 동작하는 서비스 + 아키텍처 문서. 이 시점에서 "클라우드 구축" 완료로 간주
**체크리스트**: [ ] 전체 플로우 end-to-end 테스트 통과 [ ] 인프라 코드가 git에 전부 커밋됨 [ ] 아키텍처 다이어그램 최신 상태

## 4단계. 운영 (8주차, 이후 지속)

구축은 끝났지만, 운영은 여기서 "시작"입니다. 8주차는 운영 지식을 실제로 체감하는 주간입니다.

### 8주차 — 모니터링·비용·백업·장애대응 훈련 + 회고
- 월: CloudWatch로 CPU/메모리/디스크 알람 설정, 로그를 CloudWatch Logs로 수집
- 화: 비용 점검 — 지난 7주간 실제 청구 내역 확인, Cost Explorer로 어디서 비용이 났는지 분석, 필요하면 스케줄러로 야간 자동 종료 설정
- 수: 백업 테스트 — EBS 스냅샷/S3 버저닝을 실제로 만들고, "복구가 되는지" 한 번 실제로 삭제 후 복구해보기
- 목: **장애 시나리오 훈련** — 일부러 EC2를 하나 내려보고, 알람이 오는지, 매뉴얼(runbook) 없이 복구 가능한지 확인 → 안 되면 `docs/runbook.md` 작성
- 금~주말: 8주 전체 회고 — 무엇을 배웠는지, Well-Architected Framework 관점(보안/비용/안정성/운영 우수성)에서 지금 아키텍처의 약점이 뭔지 셀프 리뷰하고 `docs/study-log.md`에 정리

**산출물**: 알람이 걸려있고, runbook이 있고, 비용이 통제되는 "운영되는" 서비스
**체크리스트**: [ ] 알람 실제 수신 확인 [ ] 백업→복구 1회 성공 [ ] runbook 작성 완료 [ ] 8주 회고 기록

**8주 이후**: 서비스를 계속 켜둘지, 정리(리소스 삭제)할지는 예산에 맞춰 결정하세요. 계속 운영하고 싶다면 이번 주 만든 알람/비용 관리 체계를 그대로 유지하면 되고, 정리한다면 `terraform destroy`로 깔끔하게 걷어낼 수 있다는 것 자체가 5주차에 Terraform으로 코드화해둔 효과입니다.
